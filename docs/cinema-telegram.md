# Экран «Кино» и Filmobot

Пользователь ищет фильм в Mini App и выбирает раздачу. Worker Jarvis на Ubuntu запрашивает RuTor, получает исходный `.torrent`, сверяет infohash с выбранной строкой и отправляет документ в личный Telegram-чат Filmobot. На Windows Filmobot получает update своим обычным polling, кладёт файл в примонтированную watch-папку и отвечает Jarvis. Домена, проброса портов и связи между локальными сетями для этого не требуется.

## Включение

Чтобы проверить поиск отдельно, нажмите «Найти фильм», введите название и нажмите «Найти раздачи». Если появится список раздач, поиск на Ubuntu работает. Этот режим включён по умолчанию (`JARVIS_CINEMA_ENABLED=search`). Если в старом `.env` осталось `false`, задайте `search` или `true` и пересоздайте контейнеры обычным деплоем. В режиме `true` поиск работает и во время подключения Filmobot. Причину недоступности передачи Mini App показывает на главной и рядом с выбором раздачи.

1. В @BotFather включите **Bot-to-Bot Communication Mode** у Jarvis и Filmobot. Числовой ID каждого бота — часть его собственного токена до двоеточия. Токены между серверами передавать не нужно. [Приватные сообщения между ботами](https://core.telegram.org/bots/features#communication-in-private-chats)
2. В уже используемом `.env` Filmobot на Windows задайте `FILMOBOT_JARVIS_BOT_IDS=<числовой ID Jarvis>`. Если Jarvis несколько, перечислите ID через запятую. Оставьте существующие настройки пользователей и привязку папки `TORRENT_SAVE_PATH`, за которой следит uTorrent. Обновите контейнер Filmobot через свой деплой.
3. В `.env` Jarvis на Ubuntu добавьте значения ниже и обновите `app` и `worker` обычным деплоем. Внешний HTTPS должен проксировать и Mini App, и путь `/telegram/cinema/receipt` в тот же контейнер `app`. Текущий локальный порт, в том числе 8370, подходит.

```dotenv
JARVIS_CINEMA_ENABLED=true
JARVIS_PUBLIC_URL=https://jarvis.ai.kilop.ru
JARVIS_FILMOBOT_ID=<числовой ID Filmobot>
JARVIS_FILMOBOT_USERNAME=@username_твоего_бота
JARVIS_CINEMA_WEBHOOK_SECRET=<случайный секрет из менеджера паролей>
```

Для секрета подходят 16–256 латинских букв, цифр, дефисов и подчёркиваний. Он нужен только Jarvis. Действующий `JARVIS_BOT_TOKEN` используется для авторизации Mini App, регистрации webhook и отправки документа.

При включении передачи приложение само регистрирует webhook для токена Jarvis. Telegram допускает одного получателя updates на токен. Остановите старый polling этого токена перед переключением. При обнаружении чужого webhook Jarvis сохраняет его и продолжает работать в режиме поиска. Для работающего бота с другим обработчиком updates нужен отдельный токен Jarvis либо явная интеграция квитанций в тот обработчик. Остальные функции Mini App доступны и во время повторной регистрации webhook. При холодном старте диалога Jarvis может отправить приветствие по @username. Файл адресуется по проверенному числовому ID. [Telegram Bot API](https://core.telegram.org/bots/api#setwebhook)

## Квитанция и восстановление

Jarvis сохраняет выдачу для конкретного пользователя на 30 минут. Выбор запускает одну команду с UUID. До отправки worker записывает в PostgreSQL точные байты и SHA-256 документа. Для повторных отправок используются та же команда и тот же файл.

| Сообщение | Содержимое |
|---|---|
| Jarvis → Filmobot | Telegram document, подпись `jarvis.torrent/1 <uuid> <sha256>` |
| Filmobot → Jarvis | Текст `filmobot.torrent/1 <uuid> <sha256> stored`, `rejected` или `uncertain` |

Filmobot принимает документы BitTorrent v1 размером до 16 МиБ от разрешённого бота в личном чате. Он проверяет SHA-256, структуру и пути, затем публикует готовый файл переименованием. `stored` подтверждает помещение файла в watch-папку. Ход скачивания фильма отслеживается в uTorrent. Filmobot хранит результат в своей БД и распознаёт повтор даже после того, как клиент забрал файл. При сбое между публикацией файла и подтверждением в БД результат может остаться `uncertain`. Сверьте очередь вручную.

Jarvis проверяет секрет webhook, отправителя, личный чат, UUID и SHA-256 квитанции. Если ответа нет, worker отправляет тот же документ до трёх раз с интервалом не менее минуты. Через пять минут экран предлагает сверить очередь. Позднюю квитанцию можно увидеть, снова открыв запуск из истории.

## Проверка

`make test-cinema-telegram` в репозитории Jarvis использует соседний проект `../kinopoisk_bot` (либо путь из `FILMOBOT_DIR`). Стенд поднимает PostgreSQL и настоящий обработчик Filmobot, подставляет HTML и метаданные RuTor и имитирует Bot API внутри Docker. Тест проверяет вход в Mini App, выбор, двойной клик, запись файла, повтор после перезапуска и квитанцию через HTTP webhook. На рабочем сервере для первой проверки выберите раздачу, которую действительно хотите добавить в uTorrent.
