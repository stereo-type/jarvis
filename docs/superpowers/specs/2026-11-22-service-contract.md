# Jarvis и контракт подключения сервисов v1

**Статус.** Архитектурное решение для первой реализации, 22 ноября 2026. Спецификация задаёт целевое поведение. Машиночитаемые примеры лежат в каталоге `examples`.

## ADR. Workflow как ядро приложения

Пользователь открывает одну Mini App и работает с уже запущенными сервисами на личном Windows-сервере. У каждого сервиса могут быть собственные клиенты. Filmobot продолжает обслуживать свой Telegram-чат, а Jarvis получает второй вход в те же операции поиска и загрузки.

| Вариант | Последствие |
|---|---|
| n8n как основной backend | Готовый редактор и полная совместимость экспортов. Каждый сценарий требует работающего n8n, чья нагрузка на этом сервере стала причиной пересмотра архитектуры. |
| Предметные плагины в ядре Jarvis | Первый экран кино легко написать вручную. Изменение последовательности действий потребует менять код приложения. |
| **Workflow в Jarvis, операции в сервисах — принято** | Экран, выбор пользователя и вызовы собираются графом. Сервисы сохраняют данные и доменную логику. Цена решения — собственные runner, хранение ожиданий и поддержка согласованного подмножества n8n. |

Mini App отображает формы, списки выбора и результаты. Backend Jarvis аутентифицирует пользователя, ведёт каталог сервисов и исполняет опубликованные графы. PostgreSQL Jarvis хранит версии, запуски и состояния шагов. Worker возобновляет фоновые шаги после перезапуска. Docker Compose управляет жизненным циклом контейнеров. Во время исполнения граф обращается к настроенному HTTP-сервису по внутренней сети. Подключение Filmobot добавляет в палитру операции его существующего экземпляра.

Предлагаемый стек для Jarvis — TypeScript, Node.js, React и PostgreSQL. Filmobot сохраняет Python, Peewee, свою БД и подключённую watch-папку uTorrent. Jarvis и Filmobot могут использовать один сервер PostgreSQL с раздельными базами и правами. Схемами данных каждого приложения владеет само приложение.

## Подключение сервиса

Соединение настраивает владелец Jarvis. В примере адрес задаёт `FILMOBOT_BASE_URL` (например, `http://filmobot:8080` в общей сети Compose), credential — `FILMOBOT_SERVICE_TOKEN`. Если проекты разворачиваются разными Compose-файлами, оба сервиса подключают к одной именованной сети и назначают Filmobot этот DNS alias. За пределами доверенной внутренней сети используется HTTPS. [Описание подключения](../../../examples/services/filmobot.connection.json)

| Поле | Что делает Jarvis |
|---|---|
| `schemaVersion`, `id`, `title` | Проверяет версию формата, адресует сервис по стабильному ID, показывает читаемое название. |
| `apiMajor` | Привязывает шаг к совместимой версии API. Ломающие изменения получают следующий major. |
| `baseUrlEnv`, `credential` | Разрешает адрес и секрет на backend. Граф хранит только ссылку на сервис. |
| `requiredHeaders` | Перечисляет обязательные для этого подключения служебные заголовки. Jarvis проверяет каждую доступную операцию Filmobot на наличие actor и request ID. |
| `contractFile` | Загружает зафиксированную копию OpenAPI 3.1 относительно файла подключения. Подойдёт описание от автора сервиса или написанное владельцем Jarvis для уже существующего API. |
| `operations` | Разрешает перечисленные `operationId`. По `summary` строится название ноды, из схем параметров и JSON-тела — поля настройки, из схем ответа — выходы. |

Перед публикацией Jarvis проверяет уникальность ID, существование каждой операции, типы входов, выходов и обязательных параметров. Например, `limit: 8` отклоняется с указанием узла `search` и разрешённого диапазона. Выходы допускают новые необязательные поля в пределах того же major. Удаление операции, изменение типа или смысла поля требуют нового major. Публикация фиксирует ревизию графа и снимок контракта. Уже запущенный экземпляр продолжает работу на своей ревизии. Изменение операций через редактор проходит ту же проверку, что и импорт файла. [Спецификация OpenAPI](https://spec.openapis.org/oas/v3.1.1.html#operation-object)

### Профиль OpenAPI первого этапа

CLI проверяет одно подключение на граф. Для разрешённых операций v1 поддерживает GET с query-полями и POST с обязательным JSON-объектом, фиксированные пути и один явный успешный статус 2xx с JSON-объектом. Авторизация — единая HTTP bearer-схема. Служебные заголовки объявляются в операции. Ошибки описываются общим `default`, при необходимости также конкретными 4xx/5xx; JSON содержит строковые `code`, `message`, `requestId`. Заголовки, которыми может управлять Jarvis, перечислены ниже в описании вызова.

Поддерживаются строки (длина, pattern, const, UUID, date-time), целые числа (minimum, maximum, default), boolean, массивы (items, maxItems), объекты (properties, required, additionalProperties как boolean) и локальные ссылки на компоненты schemas, parameters и responses. Аргумент задаётся JSON-литералом либо ссылкой на обязательное скалярное поле предыдущего шага. Для ссылки проверяется тип, ограничения конкретного значения перепроверяются при исполнении. Список выбора получает массив целиком из ответа сервиса. Узлы и ссылки валидируются по всем возможным входящим веткам. Интерактивный граф v1 начинается формой и допускает направленные связи без циклов.

Обязательный path-параметр, multipart, внешняя ссылка, альтернативная схема авторизации или другая структура ошибок требуют расширения профиля либо адаптера. CLI отклоняет такие операции до запуска и указывает место несовместимости. Расширение для n8n и длительных агентских задач планируется отдельно.

## Вызов операции

1. Jarvis проверяет подпись Telegram `initData`, свежесть `auth_date` и числовой user ID из `JARVIS_ALLOWED_USER_IDS`. Управлять подключениями и публиковать графы могут владельцы из `JARVIS_ADMIN_USER_IDS`, которым также разрешён доступ. Токены ботов и сервисов хранятся в окружении backend. [Авторизация Telegram Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app)
2. Узел задаёт `service`, `apiMajor`, `operationId` и `args`. Backend строит запрос по контракту, кодирует query-параметры и сериализует JSON-тело. Пользовательские аргументы не могут переопределять адрес сервиса, путь операции или служебные заголовки.
3. В профиле Filmobot backend передаёт `Authorization: Bearer …`, `X-Jarvis-User-Id` и `X-Request-Id`. Filmobot принимает ID пользователя только после проверки service token. Для собственных Telegram-команд Filmobot получает ID из Telegram update и применяет общий список разрешённых числовых ID. Оба адаптера передают один и тот же тип идентификатора в предметные операции. Внутренний API не публикуется через внешний ingress.
4. Операция с побочным эффектом, поддерживающая повторы, помечается `x-jarvis-idempotency: required`. Узел передачи требует эту гарантию через `requireIdempotency: true`. Удаление гарантии из контракта блокирует публикацию этого графа. До вызова Jarvis сохраняет UUID в состоянии конкретного исполнения шага. При каждом повторе меняется `X-Request-Id`, а `Idempotency-Key`, actor и тело команды остаются прежними. Для стороннего API без такой гарантии автоматический повтор изменяющей операции отключён.
5. Шаг сохраняет валидированный результат либо ошибку и переходит по событию графа. В журнал попадают run ID, шаг, операция, request ID, длительность, попытка и код результата. Токены и исходный Telegram `initData` исключаются. Агентские вызовы с длительным ожиданием обслуживает worker, UI читает состояние запуска независимо.

### Профиль Filmobot

| Операция первого среза | Вход | Успешный результат |
|---|---|---|
| `searchReleases` · `GET /v1/releases` | Строка `query` после trim, 1–200 символов. Целый `limit` от 1 до 5, по умолчанию 5. | `200` со снимком выдачи. Поля `searchId`, `expiresAt`, `releases[]`. Пустой массив — успешный поиск. |
| `enqueueDownload` · `POST /v1/downloads` | `searchId` и `releaseId` из выбранной выдачи. Служебный ключ идемпотентности обязателен. | `201` с `submissionId`, `releaseId` и `status: submitted` после помещения проверенного файла в watch-папку и записи результата. |

В старом боте `release.key` уже имеет форму `rutor:12345`. Объект раздачи с ожидаемым infohash сейчас лежит в `context.user_data["search_results"]`. Для двух входов Filmobot сохраняет снимок выдачи с владельцем и сроком жизни в своей БД. Предлагаемый срок — 30 минут, `expiresAt` в UTC. API принимает пару идентификаторов. URL, путь к файлу и ожидаемый infohash определяет Filmobot из своего снимка. Jarvis сохраняет только отображаемые результаты и ссылку на выдачу. Интерактивный узел доступен автору запуска.

**Пример обмена.** Для строки «Солярис 1972» сервис может вернуть следующий условный результат. Числа и идентификаторы иллюстрируют формат.

```json
{
  "searchId": "9d4cd32f-7db3-49e2-820b-3707ab934cbe",
  "expiresAt": "2026-11-22T12:30:00Z",
  "releases": [
    { "releaseId": "rutor:12345", "title": "Солярис (1972)", "size": "2.9 GB", "seeds": 18, "leeches": 2 }
  ]
}
```

При выборе этого варианта Jarvis отправит `{"searchId":"9d4cd32f-7db3-49e2-820b-3707ab934cbe","releaseId":"rutor:12345"}`. Пример ответа — `{"submissionId":"82a87953-97b7-4011-982f-f5439da18475","releaseId":"rutor:12345","status":"submitted"}`. Этот статус подтверждает передачу файла. Завершение скачивания фильма может подтвердить только клиент uTorrent через отдельную интеграцию. [OpenAPI с описанием операций и схем данных](../../../examples/services/filmobot.openapi.json)

### Ошибки и восстановление

Ответ об ошибке содержит `code`, безопасный для показа `message` и `requestId`. Сначала runner выбирает порт `error.<code>`, затем общий `error`. Переход выполняется после завершения разрешённых попыток.

| HTTP или событие | Действие |
|---|---|
| `400 INVALID_INPUT`, `401 UNAUTHENTICATED`, `403 FORBIDDEN` | Прекратить шаг. Неправильный ввод можно исправить новым запуском. Ошибки credentials видит владелец. |
| `404 SELECTION_NOT_FOUND` | Одинаковый ответ для неизвестной пары и попытки использовать чужую выдачу. |
| `410 SELECTION_EXPIRED` | Показать предложение начать новый поиск. |
| `422 RELEASE_CHANGED` | Infohash расходится с сохранённым снимком. Файл не публикуется. |
| `409 IDEMPOTENCY_CONFLICT` | Существующий ключ пришёл с другим телом для того же actor и операции. Завершить шаг ошибкой. |
| `409 REQUEST_IN_PROGRESS`, `429`, `502/503/504`, временный сетевой отказ | Для чтения и идемпотентной команды — до трёх попыток суммарно, задержки 1 и 2 секунды или `Retry-After`. Таймаут одной попытки для Filmobot — 60 секунд. |
| `409 HANDOFF_UNCERTAIN` | Передача могла состояться. Показать неопределённый результат и сохранить запись для сверки. Если после последней попытки ответ изменяющей операции потерян или всё ещё `REQUEST_IN_PROGRESS`, Jarvis также выдаёт этот исход. |

Filmobot хранит уникальную запись по `(actor, operationId, idempotencyKey)` с параметрами и квитанцией. Проверка существующего ключа **предшествует проверке срока поиска**. Завершённая команда возвращает исходный `201` даже после истечения срока снимка. Параллельный дубль получает ту же квитанцию или `REQUEST_IN_PROGRESS`. Ключ и результат хранятся как минимум до конца периода, когда Jarvis позволяет повторить тот же шаг. Для v1 предлагаем хранить их вместе с историей передач без автоматического удаления. Новый осознанный выбор пользователя — отдельная команда.

Транзакция PostgreSQL и переименование файла в Windows-папке имеют разные границы атомарности. Filmobot сначала резервирует команду, подготавливает и проверяет временный файл, затем фиксирует намерение публикации перед атомарным rename в том же каталоге. После rename в одной транзакции записывает квитанцию, историю и финальный статус. Если сервис упал в промежутке и uTorrent успел забрать файл, отсутствие файла в папке ничего не доказывает. После потери владельца операции worker переводит такую запись в `HANDOFF_UNCERTAIN`; повтор по ключу не создаёт второй файл. До фазы публикации подготовку можно безопасно возобновить с исключительной блокировкой команды.

## Как читать конфиг workflow

[Полный JSON графа](../../../examples/workflows/cinema-search.json) открывается с ноды `entry`. В нём зафиксированы координаты для редактора, параметры операций и все переходы.

| Последовательность | Что увидит пользователь |
|---|---|
| `query → search → found` | Форма принимает название. Граф вызывает поиск с лимитом 5. При пустой выдаче открывает `empty`. |
| `found → choose` | Список показывает название, размер и сиды. Закрытие Mini App сохраняет ожидание в PostgreSQL. Отмена и истечение срока завершают запуск без передачи файла. |
| `choose → enqueue → submitted` | Jarvis проверяет владельца, срок и наличие выбранного ID в списке. Один атомарный переход переводит ожидание в следующий шаг. Два клика приводят к одному исполнению команды. Пользователь получает квитанцию. |
| `enqueue → expired / uncertain / failure` | Истёкший выбор можно повторить новым поиском. При неопределённом результате пользователь видит просьбу сверить очередь uTorrent. |

Значение вида `{"$ref":"search.releases"}` — ссылка на выход **конкретного шага** текущего запуска. Первый сегмент — уникальный ID ноды, остальные — поля её JSON-выхода. Остальные значения `args` — литералы, поэтому `limit` можно изменить для одного графа. Форма возвращает объект с ключами полей, выбор возвращает `{"value":"rutor:12345"}`, вызов сервиса возвращает декодированное тело успеха. Успех операции и ошибку различают HTTP-статус и схемы OpenAPI. `ui.result` завершает ветку и может показать квитанцию. Геометрия `position` влияет только на редактор.

## Совместимость с другими workflow

Кино использует родной формат `jarvis.workflow/v1`. Для пяти n8n JSON из `n8n/coder/configs/v9` нужен отдельный импортёр. Он сопоставляет `type`, `typeVersion`, параметры, выражения и порты с исполнительной моделью Jarvis, сохраняет имена и координаты и выдаёт диагностику до публикации. Этот импорт позволяет менять и повторно загружать графы в рамках поддерживаемых возможностей. Режимы активности сохраняются, тестовые импорты не запускают production-триггеры автоматически. Telegram-адаптер Jarvis владеет получением updates своего токена и передаёт их нужным графам. У Filmobot остаётся свой токен.

Следующие интеграции кино — рекомендации, оценки, исключения, синхронизация и история. Для них добавляются операции того же сервиса и связи в графах. Произвольный Python-код в узлах можно добавить отдельным типом после первого среза. Профиль Filmobot уже даёт доступ к существующему Python-коду через API. Эксплуатация ядра рассчитана на своё железо и бесплатную Telegram Bot Platform. У голосового и агентских шагов v9 стоимость зависит от подключённых AI-провайдеров.
