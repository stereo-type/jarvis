# План реализации Jarvis

**Цель.** Пользователь запускает сценарий в Mini App и выполняет операции уже работающих сервисов. Первый сквозной результат — передача выбранной раздачи в watch-папку uTorrent через Filmobot.

**Архитектура.** Jarvis владеет графом, экраном и состоянием запуска. Filmobot владеет поиском, данными о раздачах и передачей файла. Основа — Node.js/TypeScript, React, PostgreSQL и Docker Compose на публичном Ubuntu-сервере. Для разработки на этой машине используются локальные Docker-цели Make. [Контракт и ADR](../specs/2026-11-22-service-contract.md)

## Карта работ

| Этап | Предлагаемые места изменений | Результат и оценка для одного разработчика |
|---|---|---|
| 1. Конфиги и контракт | Jarvis: `src/config/`, `src/validate.ts`, `tests/`, `examples/` | Команда проверяет регистрацию сервиса и граф кино без обращения к сервису. 1–2 дня. |
| 2. Два входа Filmobot | Проект Filmobot: `bot.py`, `database.py`, `torrent_rutor.py`, новый HTTP-адаптер и application service | Старый бот и новый API используют общие операции. 2–4 дня с тестами сбоев. |
| 3. Надёжное исполнение | Jarvis: `src/runner/`, `src/storage/`, миграции PostgreSQL | Граф выполняет HTTP-вызовы и переживает закрытие UI и рестарт. 2–4 дня. |
| 4. Первый экран и развёртывание | Jarvis: `src/telegram/`, `web/`, Compose | Первый сквозной сценарий на телефоне. 1–3 дня. |
| 5. Редактор и остальные функции кино | Jarvis: `web/editor/`, каталог операций. Filmobot: новые операции API | Граф редактируется в UI, пользователю доступны остальные функции действующего бота. 4–8 дней. |
| 6. Импорт и исполнение n8n v9 | Jarvis: `src/import/n8n/`, `src/runner/`, адаптеры | Все пять графов проходят согласованные сценарии. 15–26 дней. |

Этапы 2 и 3 можно вести параллельно после фиксации контракта. Этап 4 зависит от обоих. Этап 6 можно начать с независимого исследования семантики после этапа 1. Суммарный ориентир для последовательной работы — **6–13 дней до первого рабочего сценария, 25–47 дней на все шесть этапов**. Диапазоны включают проверку восстановления и настройку связности. Производительность AI-сервисов и доступность HTTPS с телефона предстоит измерить на сервере.

## 1. Валидация подключения и графа

- [x] Добавить локальные Docker-команды `make test` и `make validate`. CLI получает пути к connection, затем workflow. Контракт разрешается относительно connection. Для проверки структуры значения секретов не требуются.
- [x] Прочитать OpenAPI, зарегистрировать разрешённые операции, проверить поддерживаемую версию и профиль. Ошибка указывает файл, операцию или узел и проблемное поле.
- [x] Проверить граф первого среза: уникальные ID, существование entry и целей переходов, обязательные порты, доступность выходов из предыдущих шагов, типы аргументов и диапазон `limit`. Циклы в интерактивном графе v1 отклоняются.
- [x] Проверить настоящий пример и отрицательные варианты: неизвестная операция, ломающий major, неверный тип, превышение лимита, неверный переход или ссылка. Приёмка — рабочая команда с exit code 0 для примера, ненулевой код для ошибочного файла. Сетевые вызовы в этой фазе отсутствуют.

## 2. Подключить один экземпляр Filmobot

- [x] Выделить поиск и команду передачи раздачи из Telegram-handler’ов. Сохранить поведение `/find`, callback-кнопок и запись истории. Внутренняя модель `Release` сохраняет ожидаемый infohash. Лимит передавать до парсера результатов.
- [x] Добавить миграции для снимков выдачи с владельцем, срока, резервирования команды и квитанций. Существующие фильмы, исключения и история продолжают читаться. Для старого whitelist по username подготовить явное соответствие разрешённым числовым Telegram ID до переключения.
- [x] Реализовать две операции из OpenAPI с внутренней bearer-авторизацией. Сначала обрабатывать повторы существующей команды, затем срок жизни и владельца выдачи. Объединить запись истории и финального статуса. Для необратимой фазы публикации вести отдельное состояние из ADR.
- [x] Приёмка на тестовом томе и существующих тестах Filmobot: поиск из обоих входов, ноль результатов, чужая/просроченная выдача, подмена раздачи, расхождение infohash. Два одновременных запроса с одним ключом дают одну передачу. Потерянный ответ и рестарт после rename не кладут второй файл. Старые Telegram-команды и callback продолжают проходить через свои тесты.

Проверено в проекте Filmobot командами `make test` и `make test-postgres`. Один набор из 18 тестов прошёл в обоих окружениях. Через Telegram-диспетчер и HTTP подтверждена общая квитанция. Проверены повтор после удаления файла клиентом, одновременные запросы и сбой записи истории после передачи.

## 3. Исполнить граф с сохранением состояния

- [x] Версионировать определения, сохранять actor, revision, текущий шаг, выходы, ожидание и ключ команды в PostgreSQL. Публикация новой ревизии оставляет выполняющийся запуск на прежней.
- [x] Реализовать `ui.form`, `service.call`, `flow.hasItems`, `ui.choice`, `ui.result` из примера. Рендер формы и выбор опираются на сохранённые данные. Один атомарный переход закрывает ожидание и ставит следующий шаг в очередь.
- [x] В HTTP-адаптере разрешать адрес и credentials при вызове, валидировать ответы, учитывать таймаут, Retry-After и исход неопределённой передачи. Проставлять correlation ID и скрывать секреты в логах. При штатной остановке worker освобождает ресурсы и сохраняет возможность возобновления.
- [x] Приёмка с тестовым HTTP-сервисом и PostgreSQL: закрытие UI, повторный выбор, истечение срока и двойной клик. После перезапуска повтор запроса использует первоначальный idempotency key. Неопределённый исход переводит граф в ветку сверки с uTorrent.

- [x] Реализовать проверку подписи Telegram, возраста данных, числового whitelist и владельца запуска.
- [x] Реализовать главную, экран «Кино», поиск, выбор, историю и квитанцию. Проверять полный путь до watch-папки на изолированном стенде с Filmobot. В автономной установке «Кино» показывает статус подключения.
- [ ] После размещения на Ubuntu переключить nginx с заглушки на Jarvis, проверить публичный HTTPS и открыть JarvisApp в Telegram с телефона.


## 5. Редактирование и остальные функции кино

- [ ] Вывести в палитру операции подключённых сервисов. Разрешить владельцу создавать черновик, менять параметры, перетаскивать узлы, соединять порты, сохранять JSON и публиковать ревизию с диагностикой.
- [ ] На одном конфиге проверить изменение лимита с 5 на 3, повторную загрузку и совпадение результата с тем же графом, опубликованным через UI. Тест использует достаточно длинную выдачу. Во время редактирования действующий граф доступен пользователям.
- [ ] Подключить отдельными операциями рекомендации, исключения, доступные реакции, синхронизацию и историю. Для фоновой синхронизации предусмотреть идентификатор задания и чтение его статуса. Каждый сценарий сравнить с текущим поведением Telegram-бота. Положительная реакция сегодня только подтверждается в чате.

## 6. Импортировать пять workflow n8n v9

- [ ] Зафиксировать тестовые экспорты и матрицу поддержки всех 16 типов, их версий, операций, выражений и флагов. Учесть Code, Set, IF, Switch, NoOp, HTTP, Redis, Sheets, Telegram и его trigger, старый Cron и Schedule Trigger, Webhook и ответ, Error Trigger и транскрибацию. Валидатор показывает все несовместимости до активации.
- [ ] Первым провести `queue_v9.json` через выбор проекта и задачи, лимит параллельности и вызов coder. На тестовых данных проверить `$input.all()`, `$json`, `$('node')`, разрешённые `$env`, item linking и ветки ошибок. Код узлов исполнять отдельно от процесса API с лимитами. Отсутствующие параметры Cron сверить с эталонным поведением n8n.
- [ ] Затем проверить `manager` (текст, голос, подтверждение, webhook), `review_poller` (новый SHA, доработка), `merge_poller` (открыт, закрыт, слит) и `watchdog` (зависание, уведомление). Сохранить совместимость с manager/coder/reviewer, Google Sheets и Redis. При официальной приёмке подтвердить разрешённый способ доступа к AI-провайдерам.
- [ ] Сравнить последовательность действий и конечные статусы на записанных или изолированных ответах. В тестовом импорте исключить реальные merge и уведомления. Приёмка — импорт всех пяти файлов, воспроизводимые прогоны, изменение графа в рамках поддерживаемых узлов и повторный запуск. Сравнить нагрузку Jarvis и n8n на одном входе, измерив время внешних вызовов отдельно.

**Отдельное расширение.** Пользовательский Python-узел имеет смысл после проверки реальных случаев, где комбинации операций сервисов недостаточно. Для первого Filmobot код и зависимости уже упакованы в работающий сервис.
